## What was proven (don't re-test)
1. **Mottle was a compression artifact, not skin/LoRA.** The `img_compression=30` I was using as a motion lever plasticizes/smooths the conditioning frame. A zero-GPU CRF roundtrip test (`scratchpad/qa6h/crf/crf_compare.png`) shows CRF-30 strips skin texture; CRF-8/2 keep it. Sharp seed (comp8) → mottle gone.
2. **Softness/low-fi** had the same root (comp30 smoothing) plus the refine-skip cliff (see Open items).
3. **Color/tone drift is i2v-specific.** t2v (`QA_t2v_01_solo`) has a tight saturation range and no drift; every i2v clip drifts (frame 0 pinned, later frames free-run toward the LoRA's darker prior). Confirmed the drift is denoise-side, not decode-side (the re-anchor, a denoise-side fix, collapses it → so the offline decode A/B is moot).
4. **STG=1.0 causes late-clip flashing.** Clean ablation: B1 (STG on) = 20-frame late breakdown; B2 (STG off) = 1 residual event. **Keep STG off.**
5. **Strength is an inert motion lever with a sharp seed** (B3: 0.6→0.4 changed nothing).
6. **request.fps never reaches the temporal RoPE** (bug). `LTX2VideoGenerator.swift:481` builds `LTX2PipelineConfig` with no `fps:` arg, and the warm pipeline is built once anyway. The temporal-RoPE conditioning fps (the documented motion-vs-coherence dial) is now controllable per-render via the new `LTX2_COND_FPS` env. NOTE: `LTX2_COND_FPS=12` did NOT increase motion (B6) — likely masked by the re-anchor; see Open #1.

## The verified fidelity recipe (fixes mottle+soft+drift)
`img_compression=8` (sharp seed) + `LTX2_REANCHOR_INTERVAL=24` / `LTX2_REANCHOR_STRENGTH=0.15` (a **soft full-latent keyframe re-anchor — pose+appearance, NOT color-only**; Codex-verified: it VAE-encodes the source image and re-injects it as a keyframe latent every interval) + `LTX2_STG_SCALE=0` + face-anchor male-only/feathered. Result = B2: sharp, fine skin texture, warm tone held whole clip, no mottle, Kira + male identities locked. **But near-static (action_ratio ~1.1 vs the comp30 baseline's 3.67).**

> **⚠️ CODE BUG that likely explains the weak motion (Codex-found, verify first).** The re-anchor / multi-keyframe path **drops per-request `guidance`**: both `generateMultiKeyframe` call sites (`LTX2VideoGenerator.swift:723` and `:753`) omit `guidance: request.guidance`, so it falls back to the distilled config default **1.0**, not the 2.0 the requests sent. That means **every re-anchor render (B1/B2/B6/B7) actually ran at CFG 1.0** — and by our own earlier finding, "flat CFG 1.0 under-drives action." So the freeze may be a guidance bug as much as (or more than) the re-anchor pose-pin. **First action next session: pass `request.guidance` through both `generateMultiKeyframe` calls, rebuild, and re-run the sharp-seed recipe at CFG 2.0 before concluding anything about the re-anchor.**

## THE open problem: motion (was actively ablating this)
Hypothesis under test: the re-anchor stabilizes color but also **re-pins pose** every 24 frames → freezes motion (Codex explicitly warned re-anchoring appearance ≠ identity-only; it's a full pose anchor). If true:
- The **post-process color anchor** (`LTX2PostProcess.stabilizeColor`, `LTX2_COLOR_ANCHOR`, currently defaulted 0) is actually the *correct* motion-preserving color fix — per-frame, post-decode, never touches pose. It was labeled a "band-aid" but that judgment predates the re-anchor-freezes-motion finding.
- Likely winning recipe to try: **moderate compression (comp15–20) for motion + re-anchor OFF + post-process color anchor ON + STG off**. This gets motion (partial seed freedom) without mottle (not comp30) and color stability without pose-freeze.
