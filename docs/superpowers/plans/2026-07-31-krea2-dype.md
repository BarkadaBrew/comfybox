# Krea-2 DyPE (NTK) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Krea-2 image pipeline NTK high-resolution position handling, so 2K renders (Kira's HQ rerender, both HQ buttons) stop losing structure.

**Architecture:** Krea-2 owns a separate RoPE implementation (`Krea2Rope`) from Z-Image's `ZImageRopeEmbedder`, which is why DyPE has never applied to it. We add an optional per-axis scale to `Krea2Rope.make`, derive those scales from the token grid in both Krea-2 pipelines, and thread a `DyPEConfig` down from the server. The NTK formula is copied verbatim from the Z-Image implementation so the two models behave identically at the same scale factor.

**Tech Stack:** Swift 5.9, mlx-swift, XCTest, macOS 14+ (Apple Silicon). Server side: TypeScript (coffeeshop-server).

- The NTK formula is `theta * pow(scale, Float(d) / Float(d - 2))` — copied from `ZImageRopeEmbedder.computeNTKFreqTable:80`. Do not "improve" it; matching Z-Image exactly is the point.

- Axis 0 never scales. `Krea2Sampling.buildPositions` puts text at `[0,0,0]` and image tokens at `[0, row, col]`; holding axis 0 vanilla preserves text-image alignment.

Replace `Krea2Rope.make` (`Krea2Transformer.swift:108-120`). Note the existing local `scale` is renamed to `exponent` — it is the frequency exponent vector, and leaving both named `scale` would shadow the new parameter:

```swift
  /// pos: (L,3) -> (cos, sin) each (L, sum(axes)/2).
  ///
  /// `scales` applies NTK-aware frequency widening per axis (DyPE). A scale > 1
  /// widens theta so the model's trained frequency range covers a larger token
  /// grid — this is what keeps 2K renders structurally coherent. Axis 0 is the
  /// text/frame axis and is never scaled; widening it would break text-image
  /// alignment. Formula matches ZImageRopeEmbedder.computeNTKFreqTable exactly.
  static func make(
    pos: MLXArray, axes: [Int], theta: Float, scales: [Float] = [1, 1, 1]
  ) -> (MLXArray, MLXArray) {
    var cosParts: [MLXArray] = []
    var sinParts: [MLXArray] = []
    for (i, d) in axes.enumerated() {
      let axisScale = i < scales.count ? scales[i] : 1.0
      let axisTheta = (i == 0 || axisScale <= 1.0)
        ? theta
        : theta * pow(axisScale, Float(d) / Float(d - 2))
      let exponent = MLXArray(stride(from: 0, to: d, by: 2).map { Float($0) }) / Float(d)
      let omega = 1.0 / MLX.pow(MLXArray(axisTheta), exponent)  // (d/2,)
      let posCol = pos[0..., i ..< (i + 1)]  // (L,1)
      let freqs = posCol * omega.expandedDimensions(axis: 0)  // (L, d/2)
      cosParts.append(MLX.cos(freqs))
      sinParts.append(MLX.sin(freqs))
    }
    return (MLX.concatenated(cosParts, axis: -1), MLX.concatenated(sinParts, axis: -1))
  }
```

```swift
  /// Per-axis NTK scale factors for DyPE, as [axis0, height, width].
  ///
  /// Axis 0 is the text/frame axis and always stays at 1.0. Height and width
  /// scale by how far the current token grid exceeds the grid the model trained
  /// at: baseResolution / (spatialScale * patch), which is 1024/16 = 64 tokens.
  static func ropeScales(
    hTok: Int, wTok: Int, patch: Int, dyPE: DyPEConfig
  ) -> [Float] {
    guard dyPE.enabled, dyPE.method != .none else { return [1, 1, 1] }
    let baseTokens = Float(dyPE.baseResolution / (Krea2VAE.spatialScale * patch))
    guard baseTokens > 0 else { return [1, 1, 1] }
    return [1, Float(hTok) / baseTokens, Float(wTok) / baseTokens]
  }
```
